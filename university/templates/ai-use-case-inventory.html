01What this is+

A one-page inventory you fill in with your team. You write down the tasks across your business, ballpark the hours each one eats, note what AI could realistically do, and score every idea. The arithmetic does the prioritizing, so your first month lands on work that pays back fastest instead of the flashiest demo.

No special software required. A whiteboard, a spreadsheet, or the plain-text version below all work. The thinking is the deliverable, not the format.

02Who it's for+
  • Owners deciding where AI fits before spending a dollar on tools or consultants.
  • Department leads who keep fielding "can't we just use AI for this?" and want a defensible answer.
  • Anyone running a pilot who has to explain why this use case went first.
03What's inside+
  • A worked example with real rows across support, marketing, operations, sales, finance, and HR.
  • A blank, copy-pastable version that drops straight into a spreadsheet or doc.
  • A scoring key so everyone in the room grades the same way.
  • A note on what data to keep out of consumer AI tools while you work.
04How to use it+
  1. Brain-dump first. Go department by department. List every repetitive, rule-following, or writing-heavy task. Capture, don't judge.
  2. Estimate the time. Ballpark hours per week for each row. Rough is fine — you're ranking, not billing.
  3. Name what AI could do. Be specific: "draft the first version," "summarize the thread," "flag the outliers." If you can't name the job, it isn't ready.
  4. Score value and effort. Use the key below. Value is how much a win matters; effort is how hard it is to set up and trust.
  5. Sort by priority. Priority = Value minus Effort. Start at the top, with low-sensitivity items, and prove one win before you spread out.

Copy the blank worksheet

Paste this into a spreadsheet (it splits on the pipe |) or a doc, and start filling rows.

# | Department | Task/Process | Frequency | Time now (hrs/wk) | AI could... | Value (1-5) | Effort (1-5) | Priority (V-E) | Data sensitivity | Notes 1 | | | | | | | | | | 2 | | | | | | | | | | 3 | | | | | | | | | | 4 | | | | | | | | | | 5 | | | | | | | | | | 6 | | | | | | | | | | 7 | | | | | | | | | | 8 | | | | | | | | | | SCORING KEY Value (1-5): How much does a win here matter? 1 = minor convenience 3 = saves real time or cuts errors 5 = moves revenue, cost, or customer experience Effort (1-5): How hard to set up and trust? 1 = one prompt, use today 3 = needs setup, examples, or review 5 = new system, integration, or heavy oversight Priority = Value - Effort. Sort high to low. Start with high-priority, LOW data-sensitivity items. Prove one win, then expand.
Before you fill this in: don't paste confidential data, client PII, financials, or anything under contract into consumer AI tools while you inventory. Describe the task in the abstract. If a use case only works by feeding it sensitive data, mark it "High" and handle it with a private or approved tool later. This is general education, not legal advice — check your own obligations before moving sensitive data anywhere.

Use it responsibly

What supports this—and where it stops.

Keep the practical material attached to its evidence, method, assumptions, and limits.

Evidence

  • Workflow-owner interviews
  • Volume and time baselines
  • Representative artifacts
  • Known risks and approval requirements

Method

  1. Inventory work before tools
  2. Score value and consequence separately
  3. Expose missing evidence
  4. Prefer reversible candidates
  5. Record reasons for prioritization

Assumptions

  • Workflow owners provide materially accurate information
  • Scores are reviewed rather than treated as automatic decisions

Limitations

  • An inventory is not a technical or legal feasibility assessment
  • Incomplete workflow evidence can distort rankings
